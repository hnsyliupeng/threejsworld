# 工程血泪教训与反模式清单（源自五大仓库实测记录）

本文档汇总了 `img2threejs`、`ez-tree`、`yomotsu/vegetation`、`VictorZakharov/threejs-nanites` 和 `SamG-Coder/solstice` 开发日志与源码注释中已验证的真实缺陷、反直觉数据与工程铁律。任何生成 Three.js 场景或模型的 Agent 在执行建模与评审时必须严格遵守。

---

## 一、几何与结构反模式（Geometry & Topology）

### 1. 轮廓 IoU 骗局与 2.5D 纸片偏见（`distinctZ <= 10`）
- **实测案例**（`img2threejs` Glock-18）：模型正侧轮廓 IoU 高达 **0.986**，多角度非退化、6/8 色区匹配，但用户一眼判定为“贴图纸片”。
- **根因**：`ExtrudeGeometry` 把二维形状沿 Z 轴平推，所有顶点落在 6–10 个 Z 平面上（`distinctZ = 10`）。
- **铁律**：凡三维雕塑性实体，必须运行 `distinctZ` 检查（`round(z, 3)` 唯一值须 $> 10$），改用 **Variable-Thickness Loft + 4 分帽盖细分 + 解析场梯度法线**。

### 2. 轮廓只看 11% 的像素（删除整张脸，IoU 不变）
- **实测案例**（`img2threejs` 角色测试）：将整张面部网格删除后，轮廓 IoU 仍为 **0.8803**（与完整面部四位小数完全一致），加上整个嘴巴反而使轮廓指标反向移动 `-0.0002`。
- **铁律**：每个视觉 Pass 必须运行 **内部轮廓分层差异检查（`interior_difference`）** 与 **部件覆盖率检查（`check_part_coverage`）**，绝不能单独使用轮廓 IoU 判定成功。

### 3. 用 180° 旋转冒充左右镜像（双左手缺陷）
- **实测案例**（`img2threejs` 角色重建）：在左右对称部件中同时取反 `x` 和 `z`，等价于绕 Y 轴旋转 180°，保留了手性（Handedness），导致模型长出两只左手。
- **铁律**：左右镜像严格为矢状面反射 $(x, y, z) \to (-x, y, z)$，且镜像侧必须翻转三角形绕序（Winding），否则 `flatShading` 或背面剔除会把受光面照反。

### 4. 加宽毛发/部件企图补覆盖率，反而更秃
- **实测案例**（`img2threejs` `HAIR_PIPELINE.md`）：为了弥补侧面轮廓毛发覆盖不足，手动画宽侧边发块，结果 6 个视角全部变差（均值 `42.2% -> 40.9%`），头顶露头皮比例暴增 **+14.9%**。
- **根因**：沿直线脊线加宽截面会沿切线向旁滑移，凸起的头骨反而穿透发块表面。
- **铁律**：毛发/外壳根部必须绑定发射体曲面 `(u, v)`，运行时或构建期按径向射线执行带 `maxPush` 封顶的 **`standProud` SDF 净空步进**，并在渲染前执行仅统计头骨外侧点的 `scalp_exposure` 硬门控。

### 5. `DoubleSide` 叶片与卡片的背面黑斑
- **实测案例**（`yomotsu/vegetation` 树木/草/花）：对叶子和花瓣卡片开启 `THREE.DoubleSide` 后，卡片背面顶点法线指向下方（背离天光与太阳），导致半数植被呈现黑色斑块。
- **铁律**：采用 **`upNormalCards`**：在几何缓冲中显式复制一组反向绕序三角形，但保持顶点法线统一朝向 `+Y` 或树冠中心外侧，材质保持 `THREE.FrontSide`。

### 6. 把零厚度薄膜塞进 SDF（`implicit`）或假造实心内构
- **实测案例**（`img2threejs` 龙翼膜 / Glock 透明壳）：SDF 距离场无法表达真正的零厚度曲面，被迫将其增厚成肥皂块；而透明壳下放 8 三角形方块充当弹匣内构会在 30% 透射率下露馅。
- **铁律**：零厚度薄膜必须走 **`open-shell`**（禁止 SDF）；内部机制要么真实建模，要么诚实留空标注。

### 7. 错误的爆炸拆解（平移代替缩放）与 `root.scale` 陷阱
- **铁律**：
  - 零件爆炸预览必须**绕模型中心按位置矢量缩放**（`pos * (1 + explodeFactor)`），全体加固定偏移只会集体位移而不打开任何缝隙。
  - 隐藏根节点只能用透明材质（`opacity: 0`），绝不能设 `scale = [0.02, 0.02, 0.02]`（会连带缩塌所有子节点）。
  - 克隆根组件时必须重置 `animationRole`（禁止子部件继承 `"root"`）。

## 二、植物、LOD 与虚拟几何反模式（Foliage, LOD & Nanite）

### 8. 远距叶卡片用 $\sqrt{2}$ 面积补偿，森林变成均匀绿地毯
- **实测案例**（`VictorZakharov/threejs-nanites`）：每降一级 LOD 保留一半叶卡片。若按经典面积守恒将单张卡片放大 $\sqrt{2} \approx 1.414$ 倍，由于真实树冠叶片高度自遮挡重叠，放大后的稀疏卡片几乎不互相遮挡，投影总覆盖度激增，在 $\tau = 8$ 时整个森林变成均匀发亮的“假绿毯”。
- **铁律**：用 **4 方向 CPU Alpha 遮罩光栅化** 实测投影不透明像素数，搜索真实等效覆率缩放因子（通常在 `1.25–1.32` 之间，而非 `1.414`）。

### 9. Cluster DAG 误差用加法而非 `max` 传递
- **实测案例**（`threejs-nanites`）：`meshoptimizer` 示例使用误差累计求和，导致远处 30 像素高的橡树依然保留 ~2900 个树干三角形（比必要精度细 2–3 级）。
- **铁律**：遵循 Nanite 原论文规则：`groupErr = max(max(childErr), ownSimplificationErr)`；同时每个简化层重新按邻接关系编组并锁定组边界，使接缝在下一层消融。

### 10. Alpha Test 细枝远距蒸发与竖向纹理非幂次放大陷阱
- **实测案例**（`yomotsu/vegetation`）：普通 Mipmap 让花茎/松针在远景完全透明消失；而把花卡纹理纵向向上凑 2 的幂次（`397 -> 512`）反而提高了纵轴采样密度，迫使 GPU 更早切到更粗的 Mip 段导致茎干消失。
- **铁律**：
  - 对所有 Alpha Cutout 贴图在 CPU 构建 **覆盖率保持 Mipmap（二分倍率 + 直方图精确截断）**；
  - 对花茎等细长竖卡，纵向应向**下**缩至最近 2 的幂次或横排图集，避免不必要的粗 Mip 跃迁；
  - 树木主干向下延伸 `0.3 * (h / 7.55)` m 防止山坡露底。

### 11. 只烘焙 0°/90° 两张 Impostor 与“烘焙带光照的纹理”
- **实测案例**（`threejs-nanites`）：仅用侧面与顶视图时，从 45° 俯瞰松树会突变成一坨黑斑；而提前把太阳光照死烤进 Impostor 纹理会导致背阴面亮于真实树冠、切 LOD 瞬间闪烁。
- **铁律**：Impostor 图集至少烘焙 **0° / 30° / 60° / 90° 四个仰角**，且**仅烘焙未光照 Albedo 与物体空间法线**，在运行时统一走场景光照、阴影与大气雾。

## 三、物理材质、光照与渲染性能反模式（PBR, Shaders & GPU）

### 12. 用纯随机彩色噪声代替物理高程因果着色
- **实测案例**（`SamG-Coder/solstice` `surface.rs`）：真实材质的脏污落在低洼处、磨损出现在高凸脊。
- **铁律**：先计算带真实米制尺度的高度场 `height(u,v)`，提取 `fine (2cm)` / `medium (10cm)` / `broad (50cm)` 三尺度相对高程，再由高程驱动 `albedo`、`roughness`、`cavity`。

### 13. 在高对比光比摄影参考上用固定百分位做分割 / 不去光直接投影
- **实测案例**（`img2threejs`）：固定百分位阈值把前/侧/后三张人头图都“算”出了 `0.38` 的相同头发占比（纯属算术自洽幻觉），换成 **Otsu 类间方差分割** 后三视图立即真实拉开为 `0.387 / 0.592 / 0.747`。
- **铁律**：前景/毛发阈值严禁写死百分位；图像纹理投影前必须执行 `delight_albedo`；遇到未知光照参考时将 `roughness`/`metalness` 降级为 `report-only`；凹凸特征严禁只做亮暗颜色门控（会误把阴影当黑色材质）。

### 14. 隐形材质闪烁：像素内法线方差（Specular AA）与“天空漏光火花”
- **实测案例**（`solstice-render`）：高频法线图在远景像素内方差极大导致高光狂闪；光泽反射射线步进用尽时若直接回退天空颜色，会导致漆黑地牢里的湿石头表面冒出刺眼的“日光火花”。
- **铁律**：高频法线表面必须引入法线方差粗糙度膨胀（Specular AA）；反射射线未命中时回退至体素最近表面散射均值并做邻域辐射钳制。

### 15. GPU 帧队列阻塞与按弱端设备推算高性能帧率
- **实测案例**（`threejs-nanites`）：Chrome 在集成显卡（AMD RDNA2 iGPU）上无限提交帧队列，导致每帧在队列里排队 **5 秒**才上屏、桌面鼠标卡成幻灯片；且在高端卡占 20% 时间的树木绘制在核显占 56%，绝不能用简单倍率换算弱端帧率。
- **铁律**：WebGPU/WebGL 循环显式控制最大在途 GPU 帧数（$\le 2$ 帧），并配套 `ListGuard`（在缓冲接近上限时主动平滑放宽 $\tau$ 防止黑洞缺失）和独立分辨率缩放（仅修改渲染目标尺寸而非 Canvas 尺寸，防止缩窗闪黑）。
